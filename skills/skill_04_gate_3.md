# Skill-04: Gate3-Rubric-Assembler（Gate 3 審查與迭代總裝器）

## 1. 任務目標 (Objective)
彙整 `Skill-01` 至 `Skill-03` 之全部產出，組裝成符合教育部智慧雨林計畫管考規範的 **三份完整審查與實測文件**，嵌入 **四大核心能力評量規準（Rubric 100 分制）**、**版本改版迭代紀錄表（Iteration Log）** 與 **三方簽核欄**，並依下列兩階段規則檢核證據與簽核狀態。

## 2. 輸入參數 (Input Schema)
* `skill_01_output`: 邊界與分工定義
* `skill_02_output`: 五步測試腳本
* `skill_03_output`: 六大 KPI 矩陣與差錯日誌模板

## 3. 處理邏輯與強制防護欄 (Processing Logic & Guardrails)
1. **四大核心能力 Rubric 標準組裝（滿分 100 分）**：
   * **C1. 產業洞察與跨域溝通（25 分）**：檢核真實場域痛點洞察與跨系分工平衡度（防搭便車）。
   * **C2. AI 應用與系統整合（25 分）**：檢核原型 Demo 流暢度、人機協作增益與自動配對率。
   * **C3. 創新問題解決與落地驗證（25 分）**：檢核客觀數據前後對比、行政減壓實證與 **至少 1 次依據回饋之實質改版紀錄**。
   * **C4. 科技倫理與社會實踐（25 分）**：檢核 100% 個資去識別化與強制性人類專業覆核安全閘門。
   * **通過門檻規則**：總分 $\ge 75$ 分，且各單項能力不得低於 $18$ 分。
2. **版本迭代對照表（Iteration Log）強制嵌入**：
   * 內建 1 組該領域的「標準示範改版範例（v1.0 $\to$ v1.1）」與 2 組空白實質改版填報欄（包含：`版本演進`、`回饋來源角色`、`現場操作痛點`、`具體改版措施`、`改版效益驗證`）。
3. **一票否決品質底線自檢（Gate C / Gate 3 Veto Check）**：
   * 實測後逐項核對五項附件：20 組金標準對比表、系統差錯日誌、原型錄影或截圖、去識別化切結書、實質改版紀錄。每項填入證據編號、來源及版本。示例另標「教學示例」，空表、示例、模擬結果均不得充當場域實測證據。
   * 任一附件缺失，列明缺項及補件人，暫停送審；發現專業越權，立即停止相關操作並交人工覆核。審查者作成不通過決定時，另記理由。

## 完成條件與狀態轉移

| 狀態 | 判定條件與動作 |
|---|---|
| 套件備妥 | Skill-01 至 03 的邊界分工、腳本、KPI 與比較基準可供執行；B 表完成，C 表空白可填，A 表評分規準備妥。缺項退回相應技能。 |
| 可進場測試 | 指定負責人確認場域、資料使用及 L2 人工覆核安排，記錄同意人與日期。此時不填實測分數。 |
| 實測後待簽核 | 學生繳回已填 C 表、五項附件及對應 C1–C4 的作品；每項 KPI 可由案例追溯，至少一項真實回饋已有改版及複測紀錄。Agent 彙入 A 表，交三方審查。 |
| 驗證完成（通過） | 五項證據齊備、無未解除之否決事項、總分至少 75 且每項至少 18；A 表由計畫主持人、指導教授及產業導師完成簽核，記錄決定、理由、日期與版本。Agent 不得代簽。 |

資料待補、評分未達門檻、三方簽核未齊，各自記錄狀態。補件後以新版本重審，保留前次紀錄。單次輸出列明組別、版本、目前狀態、證據索引、缺項與下一位負責人。

## 4. 輸出格式 (Output Specification)
總裝並輸出完整的三份標準化文件架構：
1. **文件 A**：《總整式 Capstone 實作專題 — Gate 3（場域驗證與迭代）審查意見與評分表》
2. **文件 B**：《第 16 週進場驗證規準書（測試腳本、量化指標表與審查規準）》
3. **文件 C**：《第 16 週現場實測數據與迭代紀錄回覆對照表（學生團隊填報備查）》
